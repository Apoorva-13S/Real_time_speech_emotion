================================================================================
0. THE ONE-MINUTE SUMMARY
================================================================================
Think of the whole project as a factory with three rooms:

  ROOM 1 (Colab)     reads 1,440 audio clips, makes 4x copies of each with
                     small distortions (noise, room echo, speed), teaches a
                     neural network to recognise 8 emotions, and prints an
                     honest scorecard. Output: a folder called `best/` that we
                     zip into `model.zip`.

  ROOM 2 (GitHub)    checks every change automatically (tests, data path, web
                     server). When you publish a release, it stores model.zip
                     so anyone can download it.

  ROOM 3 (your PC or a server)  downloads model.zip, loads it, and gives you a
                     web page: upload a clip -> get 8 emotion percentages.

You only ever touch three commands:
  python -m ser.train      (usually run in Colab)
  python -m ser.evaluate   (check the result)
  python app/server.py     (the demo)

2. IMPORTANT: WHAT THIS DATASET ACTUALLY CONTAINS
================================================================================
Verified from the Hugging Face dataset server on 2026-11-19:

  Name        xbgoose/ravdess
  Rows        1,440
  Splits      ONE split, named "train"      <-- see the note below
  Columns     audio, modality, vocal_channel, emotion, emotional_intensity,
              statement, repetition, actor (1-24), gender
  Emotions    8 classes, already clean text labels:
                neutral 96 | calm 192 | angry 192 | disgust 192
                fearful 192 | happy 192 | sad 192 | surprised 192
  Audio       all "audio-only" + "speech" (no singing, no video)
              2.94 - 5.27 seconds per clip, 16 kHz mono is not guaranteed so we
              resample
  Actors      24 (12 female, 12 male)
  Size        ~325 MB download, ~595 MB when unpacked

THE MISCONCEPTION TO CLEAR UP FIRST
  It is easy to read "8 splits" as "8 ready-made train/validation/test sets".
  It is not. There are 8 EMOTIONS in ONE split. Nobody has divided the actors
  for you.

  That matters, and here is why, in plain terms:

    Imagine teaching someone to recognise "angry" using the voice of Person A,
    and then testing them on Person A again. They will score high by memorising
    the person, not the emotion. To know if the model really learned "angry",
    you must test it on voices it has never heard.

  So this project splits the 24 actors, not the files:

      16 actors -> training    (the model learns from these)
       4 actors -> validation  (used to pick the best epoch; not reported)
       4 actors -> test        (reported ONCE, at the end)

  If you had split randomly by file instead, the same actor would appear in
  training and testing, and the accuracy would look much better than the model
  really is. This is the number one way speech projects fool themselves.

WHY IT IS A GOOD CHOICE ANYWAY
  * Clean string labels - no filename parsing, which is exactly where the old
    version of this repo silently lost 400 files.
  * Balanced: 192 clips per emotion (neutral 96, because RAVDESS has no
    "strong" neutral).
  * Small enough to train on a free GPU in minutes, big enough to be real.
  * It is only 8 classes from 24 actors, so it is a demo-quality dataset, not a
    production one. Section 15 is honest about this.

4. RUN IT ON YOUR OWN COMPUTER (NO COLAB, NO GPU)
================================================================================
Do this first. It downloads 325 MB and takes a few minutes, but it proves your
setup works before you trust a cloud machine with your time.

4.1  Check the dataset matches expectations (about 1 minute after download):

    ser audit --config configs/local_train.yaml

  Expected output ends with "AUDIT OK" and shows 1440 clips, 24 actors, and 8
  emotion counts (neutral 96, the rest 192). If counts differ, the dataset
  changed upstream - see section 12, row "row count/actor count changed".

4.2  Prepare the data without training (fast, and it validates everything):

    ser prepare --config configs/local_train.yaml

  Expected:
      loaded 1440 clips  shape=(1440, 64000)  per_class=[192,192,...]
      wrote split: runs/local/data/splits.json
      augmented train: 3xxx clips (~65% synthetic) in ~60s
      cached npz files under runs/local/data

  Read the per-class numbers in the summary. If any class shows 0 in
  "train", the model cannot learn it. If any shows 0 in "test", that emotion
  is never measured.

4.3  Train a tiny model on CPU, just to prove the loop works (5-10 minutes):

    ser train --config configs/ci_smoke.yaml --set data.limit=null \
        data.source=/tmp/nothing train.epochs=1

  Simpler alternative that needs no dataset guesswork:

    python tests/make_offline_fixture.py --out /tmp/ravfix --actors 6 --reps 2
    ser train --config configs/ci_smoke.yaml --set \
        data.source=/tmp/ravfix data.limit=null \
        run.output_dir=/tmp/smoke \
        data.splits_file=/tmp/smoke/data/splits.json \
        data.window_s=2.0 train.epochs=1

  This uses 96 synthetic beeps instead of real speech - it trains badly on
  purpose. It is a plumbing test, not a model. Expected: an epoch line, then
  a per-class report with numbers near 0.1 (random). That is correct.

4.4  Real CPU training (optional, slow):

    ser train --config configs/local_train.yaml

  On a modern laptop this is roughly 15-40 minutes per epoch, 3 epochs. It
  works, it is just not what CPU time is for. Section 5 does the same thing in
  ~15 minutes total.

5. TRAIN FOR REAL IN GOOGLE COLAB
================================================================================
5.1  Open the notebook
  * Go to https://colab.research.google.com
  * File > Open notebook > GitHub tab
  * Paste:  Apoorva-13S/Real_time_speech_emotion
  * Choose  notebooks/colab_train.ipynb

  If it asks for permission on a private repo, use a token, not a password
  (GitHub > Settings > Developer settings > Personal access tokens > Fine
  grained > Repository access: this repo > Contents: read).

5.2  Turn on the free GPU
  Runtime > Change runtime type > Hardware accelerator > T4 GPU > Save.
  Free Colab gives you a T4 with 15 GB. That is plenty here.

5.3  Run the cells in order
  Click the play button on each cell, top to bottom. Do NOT use "Run all" the
  first time: you want to read the checkpoint output of each cell.

  Cell by cell, and what "good" looks like:

  Step 1  prints python / torch versions and "cuda: True" and "gpu: Tesla T4".
          If cuda is False, redo 5.2 (a different runtime was assigned).

  Step 2  clones the repo. Ends with "working directory: /content/repo".

  Step 3  installs dependencies and prints versions. If it stops on an
          assertion about numpy, re-run the cell once - Colab sometimes
          installs numpy 2 over an older librosa.

  Step 4  mounts Google Drive (optional). It shows a permission page: sign in,
          allow. If you skip this cell, set USE_DRIVE = False so checkpoints
          stay on the Colab machine - you lose them on disconnect.

  Step 5  downloads the dataset and prints:
              clips   : 1440
              actors  : 24
              duration: min 2.94  median 3.67  max 5.27 s
              angry 192 ... neutral 96 ...
              DATASET OK
          If this fails, stop. Nothing after it can be right.

  Step 6  trains. You will see one line per 20 steps and one summary line per
          epoch:
              epoch 1/6: loss=1.62 val_acc=0.41 val_macroF1=0.36 val_wF1=0.40
          Macro F1 should rise every epoch. Roughly 0.45-0.60 on this dataset
          after 6 epochs is a normal, honest result. Takes ~15-20 minutes total.

  Step 7  prints the test report. Read section 6 before believing it.

  Step 8  upload a WAV and see predictions. Use a short clip of your own voice.

  Step 9  builds /content/model.zip and downloads it to your computer.
          Keep that file: it is your trained model.

  Step 10 downloads run_record.json - the "recipe" for your result. Commit it
          to the repo or keep it with your report. Without it, nobody (including
          you, next month) can reproduce the number.

5.4  If Colab disconnects mid-training
  Free Colab disconnects after ~90 minutes idle, and sometimes for no reason.
  Because configs/colab_train.yaml has `resume: true` and checkpoints go to
  Drive every epoch:
    - re-open the notebook, re-run Steps 1-5
    - Step 6 will detect runs/full/checkpoints/last.pt and continue from the
      next epoch. The printed line says "resumed from ... at epoch N".
  If it starts from epoch 1, your Drive was not mounted - check Step 4 printed
  "/content/drive/MyDrive/ser_runs/full".

5.5  What the training actually does (plain language)
  * Base model: facebook/wav2vec2-base. It already understands speech sounds
    from 960 hours of audio. We teach it one new skill: 8 emotion categories.
  * We freeze its "hearing" part and train only the small classifier on top.
    With 1,152 training clips, that is the difference between learning and
    memorising.
  * Each training clip is copied 2-6 times with small distortions: quieter or
    louder, room echo, telephone-quality filtering, +-8% faster or slower,
    light background noise. Same emotion, different "recording". This teaches
    the model to ignore the microphone and listen to the voice.
  * `calm` and `surprised` are rare-ish and historically the classes models
    fail at, so they automatically get more copies.
  * Validation (4 unseen actors) picks the best epoch. Test (4 different
    unseen actors) is used once, at the end, and never for choices.

6. UNDERSTAND THE RESULTS (HOW TO TELL A GOOD RUN FROM A FAKE ONE)
================================================================================
You will see a table like this. Here is what each column means:

    class        prec   rec     f1  support
    angry        0.82   0.79   0.80       46
    calm         0.61   0.55   0.58       46
    ...
    accuracy          0.62
    macro F1          0.58      <- average over all 8 classes, equally
    weighted F1       0.61      <- average weighted by how many clips each has

THREE NUMBERS, AND WHY ALL THREE

  1. accuracy = "how often is the top guess right". Easy to inflate and easy to
     misunderstand: if 30% of clips were one emotion, a lazy model that always
     answers that emotion would score 30% while knowing nothing.

  2. macro F1 = the average of the per-class F1 scores, each class counting
     equally. THIS is the number to trust. If two classes are never predicted,
     macro F1 drops immediately.

  3. weighted F1 = like macro, but classes with more clips (and classes with
     ZERO clips) count less or not at all. The previous version of this project
     reported weighted F1 0.5267 while two of its eight classes had zero test
     data - the reported number literally could not see the failure.

  The project reports all three, and marks classes with no test data as
  "NO TEST DATA" instead of quietly averaging them away.

RED FLAGS - stop and fix before shipping
  [ ] accuracy <= majority baseline (printed with the report). You have a model
      that has learned nothing.
  [ ] any class recall = 0.00. The model cannot recognise that emotion at all.
      Usually caused by too few clips for it - check the per-class counts.
  [ ] macro F1 much lower than weighted F1 (e.g. 0.35 vs 0.62). Some classes
      are being sacrificed for the big ones.
  [ ] validation score much higher than test score (e.g. 0.75 vs 0.45). The
      model memorised the validation actors. Check that no actor appears in two
      splits: `runs/*/data/split_report.json` has a "problems" list.
  [ ] a suspiciously perfect score (95-100% on 8 emotions from 24 actors).
      For this dataset that almost always means train/test leakage, or that
      you evaluated on training data.

WHAT IS A REALISTIC SCORE
  Published results on acted corpora like RAVDESS are roughly 60-80% accuracy
  with bigger models, more data, and 4-6 classes. With 8 classes, 16 actors
  for training, and speaker-disjoint testing, expect:
      accuracy   0.45 - 0.65
      macro F1   0.40 - 0.60
  Anything above 0.80 here deserves suspicion before celebration, and anything
  below 0.35 means something is wrong (usually data, not the model).

--- OPTION A: GitHub Release (simplest, recommended to start) ----------------

            Description:
                wav2vec2-base, 8 emotions, xbgoose/ravdess
                test accuracy 0.xx | macro F1 0.xx
                Trained on 16 actors, tested on 4 unseen actors
            Attach model.zip to the "Attach binaries" box
            Publish release

  Files over 25 MB in a normal git commit are rejected; release assets allow
  2 GB. That is exactly why the model goes here and not in the repo.

  7A.3  The release URL you need later is:
            https://github.com/<user>/Real_time_speech_emotion/releases/download/v1.0.0/model.zip

--- OPTION B: Hugging Face Hub (if you want from_pretrained) ------------------

    pip install huggingface_hub
    huggingface-cli login                     # paste a WRITE token

    python - <<'PY'
    from huggingface_hub import HfApi
    HfApi().upload_folder(
        folder_path="best",                   # your unzipped checkpoint
        repo_id="YOUR-NAME/ser-ravdess",
        repo_type="model",
    )
    PY

  Then the model is loadable with:
      AutoModelForAudioClassification.from_pretrained("YOUR-NAME/ser-ravdess")
  and you can skip the download step in section 9.

--- OPTION C: automated release via GitHub Actions ---------------------------

  .github/workflows/release.yml verifies a bundle and attaches it to a release:
    * it refuses a bundle whose label order differs from the repo's classes
    * it refuses a truncated weight file
    * it publishes SHA256SUMS next to the zip
  Trigger it from the Actions tab: "Release model bundle" > Run workflow >
  paste a direct download URL for model.zip + a tag name.
  Note: Google Drive share links are NOT direct links; use a release asset,
  an HF Hub URL, or a link that ends in the file itself.

8. DEPLOY: GITHUB ACTIONS
================================================================================
There is nothing to install: GitHub runs the workflows in .github/workflows/
automatically. Two are included.

8.1  ci.yml - runs on every push and pull request
     Five checks, about 3 minutes total:
       lint-and-test     every .py file compiles; unit tests pass; the full
                         data path runs on a 128-clip offline fixture
                         (split -> augment -> cache) on Python 3.10 and 3.12
       dataset-contract  asks the Hugging Face dataset server whether
                         xbgoose/ravdess still has 1,440 rows / 24 actors /
                         8 labels. If the dataset is re-uploaded with different
                         shape, you find out before you train on it.
       train-smoke       manual only (Actions > CI > Run workflow). Downloads
                         torch + wav2vec2 (~500 MB) and trains one epoch on
                         synthetic audio, to prove the real loop still works.

     Where to look:
       github.com/<user>/Real_time_speech_emotion/actions
       Green tick = good. Red cross = click it, open the failed step, read the
       last ~20 lines. Section 12 maps the usual messages to fixes.

8.2  release.yml - publishes a model bundle (section 7, Option C)

8.3  What CI deliberately does NOT do
     * It does not train the real model. Training needs a GPU and 15 minutes of
       compute; doing it on every push would be slow and wasteful. Training is
       Colab's job.
     * It does not deploy a live website. If you want one, the model is a static
       file plus a small server - see section 9 part D.

8.4  Protecting the main branch (optional, recommended)
     Settings > Branches > Add branch protection rule >
       Branch name pattern: main
       tick "Require status checks to pass before merging"
       tick "lint-and-test"
     Now nobody (including you at 2 a.m.) can merge a change that breaks the
     tests.

9. RUN THE DEMO
================================================================================
Part A - download and load the model

  A.1  Get model.zip (from the release, or the file Colab downloaded).
  A.2  Unzip so that you have a folder, e.g.:
           C:\Users\you\models\ser\model\     (Windows)
           ~/models/ser/model/                (mac/Linux)
       Inside it: config.json, model.safetensors, preprocessor_config.json
  A.3  Start the server from the repo folder, pointing at that folder:

           python app/server.py --model "C:\Users\you\models\ser\model"

       or with the CLI:

           ser serve --model ~/models/ser/model

       You should see:
           model=.../model  device=cpu  labels=['angry','calm',...]  window=4.0s
           serving on http://0.0.0.0:8000  (model_loaded=True)

  A.4  Open http://localhost:8000 in a browser. The badge top-right should say
       "trained model". If it says "no model loaded", the path is wrong - see
       section 12.

  A.5  Upload a 2-6 second WAV of speech (your own voice is best) and press
       Analyse. You get 8 percentages. The highest is highlighted.

  The model card note in the UI is deliberate: this is acted speech from 24
  actors; it estimates acoustics, not a person's real feelings.

Part B - command line instead of the web page

    ser predict --audio "C:\path\to\clip.wav" --model ~/models/ser/model

  Expected: a ranked list with percentages and a bar chart in text.

Part C - live microphone (optional)

    ser serve ... does not capture a mic; the browser does. Two options:

    C.1 Browser recording (works everywhere, nothing to install):
        On the demo page press "Record 4 s", allow the microphone, then
        Analyse.
        - Chrome/Edge/Firefox on localhost: fine.
        - Safari on iOS requires HTTPS; localhost over http will not ask.
        - If the button does nothing, the page is not on localhost and not on
          HTTPS. See section 12.

    C.2 Native mic from the terminal (Linux/macOS):
        ser predict needs a file, so use the live module:
            python -c "import sys;sys.path.insert(0,'src');from ser.live import main;main()" --model ~/models/ser/model
        or simply:
            python src/ser/live.py --model ~/models/ser/model
        First run `python src/ser/live.py --list-devices` and pick your real
        input device - the default is often a webcam or HDMI, which records
        silence and makes it look broken.

Part D - putting it on the internet (optional)

  The demo is a single Python file (app/server.py) with no framework, so most
  free hosts run it as-is. The requirement is always the same: the host must be
  able to run `python app/server.py --port $PORT` and the model folder must be
  present.

  * Hugging Face Spaces (free, no card): create a Space with the "Docker" SDK,
    copy app/ + src/ in, put the model in the repo via git-lfs, and set the
    start command to `python app/server.py --port 7860`. Spaces are public by
    default.
  * Render / Railway / Fly.io: free or cheap tiers; start command
    `python app/server.py --port $PORT`; add model.zip download as a build
    step or commit the unzipped model with git-lfs.
  * Streamlit Community Cloud: needs a ~15-line streamlit wrapper around
    ser.predict.EmotionPredictor. Free, but the app sleeps after inactivity.

  Whichever you pick: keep model.zip under 500 MB and set the host's memory to
  at least 2 GB. wav2vec2-base is ~380 MB in RAM plus the Python runtime.

12. TROUBLESHOOTING: SYMPTOM -> CAUSE -> FIX
================================================================================
Jump to the message you see. Numbers in brackets are the matching section above.

--- SETUP -------------------------------------------------------------------
"python: command not found" / "'python' is not recognized"
    Python is not installed, or not on PATH.
    -> Windows: reinstall from python.org, TICK "Add Python to PATH".
    -> macOS/Linux: try `python3` instead of `python`.

"ser: command not found"

--- TRAINING ----------------------------------------------------------------
"CUDA out of memory"
    The batch does not fit the GPU.
    -> lower it:  --set train.batch_size=4  (then 2)
    -> shorten clips: --set data.window_s=3.0
    -> in Colab: Runtime > Restart runtime, then re-run (a previous run may be
       holding memory)
    A T4 with 15 GB handles batch 8 x 4 s comfortably; an OOM means something
    else is also loaded.

Training runs on CPU / "NOTE: training on CPU"
    Colab assigned a CPU runtime.
    -> Runtime > Change runtime type > T4 GPU > Save, then re-run from Step 1.
    Locally this is normal; section 4.4 explains what to expect.

Loss stays the same or becomes "nan"
    (a) learning rate too high -> --set train.lr=0.00001
    (b) fp16 trouble on an old GPU -> --set train.fp16=false
    (c) a corrupt clip got through -> re-run `ser prepare` and read the
        "skipped" count; it should be 0.

Every epoch's macro F1 is ~0.12-0.15 (chance level)
    The model is not learning anything - almost always data.
    -> run `ser audit` and look for a class with 0 clips
    -> check data.window_s is 4.0, not 0.4
    -> check the report says "labels=['angry','calm',...]" (8 sane names)

Validation great, test terrible (0.75 vs 0.45)
    Actor leakage. Open runs/*/data/split_report.json and read "problems".
    If it mentions "appear in both", delete that splits.json and re-run:
        rm runs/local/data/splits.json && ser prepare ...

"the training split is empty" / "train split has no examples"
    data.limit is too small: every loaded clip landed on held-out actors.
    -> raise data.limit, or lower data.val_frac / data.test_frac.

Colab: "Runtime disconnected" mid-epoch
    Free-tier behaviour. Checkpoints are written every epoch (and to Drive if
    Step 4 ran). Re-open, re-run Steps 1-5, and Step 6 resumes
    (config has `resume: true`). At most one epoch is lost.

Colab: "You are over your disk quota" or Drive writes hang
    Each epoch writes ~380 MB of weights plus ~700 MB of optimiser state.
    -> set `train.resume: false` so last.pt is not rewritten, and
    -> keep only runs/full/best and the latest epoch on Drive; delete older
       epoch_N folders after training finishes.

================================================================================
14. GLOSSARY
================================================================================
accuracy          fraction of guesses that were right. Hides class failures.
augmentation      making extra copies of a clip with small distortions, so the
                  model does not memorise one recording.
actor / speaker   a person in the dataset. 24 here. Splitting by actor is what
                  makes the score meaningful.
checkpoint        a saved copy of the model at one moment (each epoch).
epoch             one full pass over the training data.
F1                balance of precision (when it says "angry", how often is it
                  right?) and recall (of the truly angry clips, how many did it
                  find?). Macro F1 averages it equally over classes.
fp16              half-precision maths on the GPU, ~2x faster, slightly less
                  exact. Needs a "scaler" to avoid silently broken gradients.
inference         using a trained model to make predictions (no learning).
leakage           test data influenced training or model choice. Makes scores
                  look better than reality. Prevented by actor-disjoint splits.
macro / weighted  unweighted average over classes / average weighted by class
                  size. Macro exposes dead classes; weighted hides them.
wav2vec2          a speech model pretrained on raw audio; we attach a small
                  8-way classifier and fine-tune that.
fine-tuning       continuing to train a pretrained model on your own small data.

================================================================================
15. HONEST LIMITS OF THIS PROJECT
================================================================================
Read this before quoting a number to anyone.

1. The dataset is small and acted. 24 actors reading two fixed sentences in a
   studio, in extreme performed emotions. Real conversation is far harder:
   people express emotion with subtlety, context and words, none of which this
   model sees. Expect a large drop on natural speech.

2. 8 classes is the hard version. "Calm" vs "neutral" and "fearful" vs
   "surprised" are acoustically close; published work often merges them.
   instructions.txt explains how to switch to 7 classes (calm -> neutral).

3. The model has never been tested on a second dataset. The previous version of
   this repo compared checkpoints on TESS, but selected its "best" checkpoint
   using that very test set, so the reported 52.54% is optimistic. This
   pipeline fixes the method (selection on validation) but the only honest
   cross-corpus check is still missing - that is the next experiment worth
   running.

4. It is not a lie detector or an emotion sensor. It maps acoustic patterns to
   labels learned from actors. Two speakers can share acoustics with different
   feelings. Never use it to judge a person, and never present its output as a
   measurement of how someone feels.

5. Latency was not benchmarked here. On CPU, expect roughly 100-400 ms per 4 s
   clip for wav2vec2-base on a modern laptop; the demo prints its own timing so
   you can measure yours instead of trusting that range.

6. Licensing: RAVDESS is distributed for research (CC BY-NC-SA style terms on
   the original distribution). Check before publishing weights or using this
   commercially.
