     live loop.

C-2  Classes present in the model but absent in the test set
--------------------------------------------------------------------------
Facts: 8 output labels; test set contains 6. `calm` and `surprised` have zero
support. Any prediction of those two classes is automatically wrong, yet
sklearn's *weighted* F1 counts them with weight 0, so the reported 0.5267
never shows the damage.
Evidence: cell 88 -> macro avg F1 0.36, weighted avg F1 0.48; calm/surprised
rows are all zeros.
Two defensible options:
  (a) 6-class model: merge calm+neutral into neutral, map ps -> surprised,
      retrain, and state "6 classes" everywhere; or
  (b) keep 8 classes and guarantee all 8 appear in the test set, then report
      BOTH macro and weighted F1 plus a per-class table.
Never report a single weighted-F1 number for an 8-class model tested on 6.

C-3  The reported checkpoint was selected using the test set
--------------------------------------------------------------------------
Evidence:
  * cell 86: "best" is chosen by validation weighted F1 ->
        epoch1 0.4710, epoch2 0.6300, epoch3 0.6461  => best = epoch_3
  * cell 92: TESS per epoch -> epoch1 40.12, epoch2 52.54, epoch3 48.12,
        and "Combined best" = 48.12 (i.e. epoch_3)
  * cell 94: the backup copies `combined_model_v1/epoch_2` as
        "best_tess_checkpoint"
So the README's 52.54% is the maximum over three checkpoints scored on TESS -
an optimistic estimate. The validation-best model is materially worse on TESS.
Fix:
  * Create a real held-out set: split speakers into train / val / test.
    Two datasets is not enough (CREMA-D + RAVDESS train, TESS test, nothing
    left for val).
  * Select on val only; report test once, for the selected checkpoint.
  * If you must keep TESS as the reported set, report the whole epoch curve
    (40.12 / 52.54 / 48.12) and label 52.54% as "best of three epochs on the
    reported set", never as an independent test score.

C-4  Evaluation filters samples by their own prediction (survivorship bias)
--------------------------------------------------------------------------
Where : cells 98-99 and the surrounding text.
Code  :
    if predicted not in set(emotion_map.values()):
        skipped.append(filename)
        continue
Evidence: cell 98 printed "Evaluated: 2400 / Skipped: 400 / Accuracy: 99.88%"
and the classification report has NO "neutral" row. The pipeline never
produced a label that mapped into the taxonomy (its neutral-ish label likely
differs), so all 400 neutral files were deleted from the scoring set - after
seeing the prediction.
Consequence: accuracy is computed only on samples the model handled, which is
exactly the bias evaluation must avoid.
Fix: decide the label mapping BEFORE scoring, map every prediction through an
explicit alias table, and count unmapped predictions as errors (or report
coverage separately), e.g.:
    predicted = alias.get(raw_label, "__other__")
    # "__other__" then contributes as a wrong prediction to y_pred
Also report: n_total, n_scored, coverage, and accuracy over n_total.

C-5  TESS is inside the compared model's training data
--------------------------------------------------------------------------
Facts: Dpngtm/wav2vec2-emotion-recognition reports TESS among its training
datasets (notebook cell 2). Cell 98 then scores it on TESS and gets 99.88%.
That is textbook train/test contamination, not a baseline.
Fix:
  * Delete that row, or label it "in-domain / contaminated, not comparable".
  * For an honest baseline, evaluate the third-party model on a corpus it did

Where : cells 69-71.

H-5  Batch-cache resume can mix stale data across splits
--------------------------------------------------------------------------
Where : cell 85 process_split() - it skips batch_id already present on disk.
Symptom class:
  * A crash mid-write leaves a truncated .npz that is skipped forever.
  * Re-running the index with a different split (different random_state, fixed
    ps mapping, dedupe change) does NOT invalidate old batch files, so train
    batches can contain rows that are in the new validation/test split.
  * Silent metric inflation that no error message will ever reveal.
Fix:
  * Version the cache directory by a fingerprint of the split:
        fp = hashlib.sha256(
            "".join(sorted(train_df["path"])).encode()).hexdigest()[:12]
        split_dir = save_root / f"train-{fp}"
    or write a manifest.json with counts + max mtime and refuse to reuse on
    mismatch.
  * Validate every npz on load: same number of arrays, labels dtype int64,
    len(input_values) == len(labels).
  * Delete + rebuild when the index changes (make it explicit, not automatic).
  * Never write a partially finished batch: np.savez to a tmp file then
    os.replace().

H-6  Missing LR warmup / scheduler / GradScaler
--------------------------------------------------------------------------
Where : cell 86.
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)  # no scheduler
    with torch.autocast(device_type="cuda", dtype=torch.float16): ...
    loss.backward(); ... optimizer.step()                        # no scaler
Why it matters: wav2vec2 fine-tuning with a freshly initialised classification
head needs LR warmup (typically 10% of steps) and often a lower backbone LR;
without it the first steps can destroy the pretrained encoder. fp16 autocast
without a GradScaler can silently underflow small gradients (NaN/plateau).
Fix:
    from transformers import get_cosine_schedule_with_warmup
    from torch.amp import GradScaler
    total = len(train_loader) * EPOCHS // ACCUMULATION_STEPS
    sched = get_cosine_schedule_with_warmup(optimizer,
              int(0.1 * total), total)
    scaler = GradScaler(enabled=(device.type == "cuda"))
    ...
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)
    clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(optimizer); scaler.update(); sched.step()
Also log the LR and grad norm; a stuck grad norm > 10 means instability.

H-7  Class imbalance with no correction
--------------------------------------------------------------------------
Measured (cell 76, final index):
    angry 1172, disgust 1172, fearful 1171, happy 1170, sad 1172,
    neutral 948, calm 152, surprised 152   (calm/surprised = 2.1%)
Consequences: the model rarely predicts calm/surprised (it costs little in
weighted loss), and those two classes are exactly the ones missing from the

H-8  Checkpoint storage blow-up on Google Drive

Step 3 - does 16 kHz mono float32 work?

    sd.check_input_settings(device=None, channels=1, samplerate=16000,
                            dtype="float32")
    a = sd.rec(16000, samplerate=16000, channels=1, dtype="float32",
               device=None); sd.wait()
    print(a.shape, float(np.abs(a).max()), float(np.sqrt((a**2).mean())))

      PortAudio, or the mic is muted by a hardware switch.

    (peak high but RMS low) distorts normalisation: subtract the mean first.

    some devices this fails or silently runs at 48 kHz. Force with
    sd.check_input_settings first, and confirm with a known-tone test
    (play 440 Hz, FFT peak should land at 440).

        flat    = np.concatenate(feats).astype(np.float16)
        tmp = str(path) + ".tmp.npz"

        with np.load(path) as z:                 # no allow_pickle needed

            off = np.concatenate([[0], np.cumsum(lengths)])
            return [data[off[i]:off[i+1]].astype(np.float32)
                    for i in range(len(lengths))], z["labels"]

(f) Live loop with device selection, RMS gate and clean shutdown (M-1..M-3):
    import os, queue, time, numpy as np, sounddevice as sd, torch
    from transformers import pipeline
    MODEL = os.environ.get("SEMO_MODEL",
                           "Dpngtm/wav2vec2-emotion-recognition")
    MIC   = os.environ.get("SEMO_MIC")           # index or name, or None
    SR, BLOCK = 16000, 3
    clf = pipeline("audio-classification", model=MODEL,
                   device=0 if torch.cuda.is_available() else -1)
    q = queue.Queue()
    def cb(indata, frames, t, status):
        if status: print(status, flush=True)
        q.put(indata.copy())
    with sd.InputStream(samplerate=SR, channels=1, dtype="float32",
                        blocksize=SR // 4, device=MIC, callback=cb):
        buf = np.zeros(0, dtype=np.float32)
        while True:
            buf = np.concatenate([buf, q.get().ravel()])[-SR * BLOCK:]
            if len(buf) < SR * BLOCK:
                continue
            rms = float(np.sqrt((buf ** 2).mean()))
            if rms < 0.005:
                continue
            x = buf / max(float(np.abs(buf).max()), 1e-6)
            t0 = time.perf_counter()
            out = clf({"raw": x, "sampling_rate": SR}, top_k=3)
            dt = time.perf_counter() - t0
            print(" | ".join(f"{r['label']} {r['score']*100:.1f}%"
                             for r in out) + f"   [{dt*1000:.0f} ms]",
                  flush=True)
